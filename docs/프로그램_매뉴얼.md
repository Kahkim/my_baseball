# 나의 구단주가 되어라 — 프로그램 매뉴얼 (학생 구현 스펙)

이 문서는 **여러분이 실제로 짜야 하는 함수의 완전한 스펙**입니다. 게임 규칙이나 프로그램 실행
방법(서버 켜는 법 등)은 [`게임_규칙_및_운영_매뉴얼.md`](./게임_규칙_및_운영_매뉴얼.md)를 보세요.

이 문서와 코드가 어긋나면 코드가 정답입니다 — 원본 스펙은 `kbo_sim/student_api.py` 파일 맨 위
docstring에 있고, 이 문서는 그 내용을 학생이 읽기 편하게 정리·보강한 것입니다.

## 1. 구현해야 하는 것

파이썬 파일 하나(`본인이름.py`)에, **파일 최상위**(클래스나 다른 함수 안이 아님)에 아래 시그니처의
함수를 **정확히 이 이름·이 인자 이름·이 인자 순서**로 정의해서 제출합니다.

```python
def decide_lineup(is_offense, my_team, opponent_team, matchups, context, rng):
    ...
    return lineup   # pCode(정수) 리스트. 길이는 9(공격) 또는 10(수비)
```

엔진은 이 함수를 **키워드 인자로** 호출합니다. 즉 인자 이름 하나라도 다르면(`off` 등으로 줄여
쓰는 것 포함) 호출 자체가 실패해 실격 처리됩니다. 이름·순서를 절대 바꾸지 마세요.

### 언제, 몇 번 호출되는가

`decide_lineup()`은 **이닝이 시작될 때 한 번에 4번** 호출됩니다(양 팀 × 공격/수비). 초/말
공수교대 시점에는 다시 호출되지 않고, 이닝 시작에 확정된 명단이 그 이닝 내내 쓰입니다.

```
N회 시작 → ① 홈팀 수비  ② 원정팀 수비  ③ 원정팀 공격  ④ 홈팀 공격
        → N회초 진행 → N회말 진행 → (N+1)회 시작 → ...
```

수비를 먼저 정하므로 공격 결정 시점에는 이번 이닝 상대 투수/포수를 이미 알 수 있습니다. 다만
**말 공격 명단도 초가 진행되기 전에 확정**되므로, 홈팀이라면 초 공격 결과(점수 변화 등)가 아직
반영되지 않은 상태에서 말 공격 명단을 결정하게 됩니다.

## 2. 인자 상세

### `is_offense: bool`
`True`면 공격(타순 9명), `False`면 수비(수비진 10명)를 결정해야 합니다.

### `my_team: pandas.DataFrame` — 우리 팀 전체 선수(타자+투수), 한 행 = 선수 1명

실제 KBO 시즌 기록 컬럼과 이번 경기 진행 상태 컬럼이 함께 들어 있습니다.

| 구분 | 컬럼 | 설명 |
|---|---|---|
| 식별 | `pCode` | **진짜 키.** 반환값은 항상 이 값으로 채웁니다. |
| 식별 | `name`, `shortName`, `displayId` | 사람이 보기 위한 이름(표시용일 뿐, 로직에서 쓸 필요 없음) |
| 식별 | `team`, `backNo`, `position`, `throwBat`, `role` | `position`은 `내야수`/`외야수`/`포수`/`투수` 중 하나(고정값). `role`은 `'타자'` 또는 `'투수'` |
| 경기 상태 | `health_pct` | 0~100. 현재 체력(100=쌩쌩, 0=탈진). **절대 회복되지 않고 계속 누적됩니다.** |
| 경기 상태 | `swing_count`, `swing_target` | **타자(수비수 포함)만 유효**, 투수 행은 `NaN`. 누적 스윙수/이 선수의 이번 경기 목표치(개인차 있음, 약 20 안팎) |
| 경기 상태 | `pitch_count`, `pitch_target` | **투수만 유효**, 타자 행은 `NaN`. 누적 투구수/이 선수의 이번 경기 목표치(개인차 있음, 그 투수의 실제 등판당 평균 투구수 근처) |
| 실제 타격기록 | `AVG, G, PA, AB, R, H, 2B, 3B, HR, TB, RBI, SAC, SF, BB, IBB, HBP, SO, GDP, SLG, OBP, OPS, MultiHit, RISP_AVG, PH_AVG, PA_eff` | 타자 행에서 유효, 투수 행은 `NaN` |
| 실제 투구기록 | `ERA, W, L, SV, HLD, WPCT, IP, IP_f, ER, WHIP, CG, SHO, QS, BSV, TBF, NP, OAVG, WP, BK, TBF_eff, NP_per_G, target_pitch_base` | 투수 행에서 유효, 타자 행은 `NaN` |

**⚠️ 컬럼명 겹침 주의**: 원본 CSV 스키마상 `H`, `2B`, `3B`, `HR`, `BB`, `HBP`, `SO`, `SF`, `SAC`,
`IBB` 는 타자 쪽에서는 "이 선수의 기록"이고 투수 쪽에서는 "이 투수가 내준 기록"으로, **같은
컬럼명을 역할에 따라 다른 의미로 씁니다.** 한 DataFrame에 타자 행과 투수 행이 섞여 있으므로,
이 컬럼들을 볼 때는 반드시 `row["role"]`(또는 `position == "투수"`)로 먼저 걸러서 보세요.
(예시는 아래 4절 샘플 코드처럼 `my_team["role"] == "타자"`로 먼저 나눠두는 것을 권장합니다.)

**투수를 고를 때 특히 봐야 할 컬럼**: `NP_per_G`(그 투수의 실제 등판당 평균 투구수 = 스태미너),
`pitch_count`(이번 경기 누적 투구수), `pitch_target`(이번 경기 체력 한계치). 방어율만 보고
고르면 "2이닝만 던지고 방어율 0.00"인 원포인트 계투를 선발처럼 오래 쓰는 실수를 하게 됩니다 —
그런 투수는 15구만 던져도 체력이 바닥나 대량실점으로 이어집니다.

### `opponent_team: pandas.DataFrame`
`my_team`과 완전히 동일한 스키마입니다. **상대 팀 선수들의 체력(`health_pct` 등)도 전부
보입니다** — 상대 투수가 이미 많이 지쳤다면 그걸 감안해 이번 이닝 공격 전략(누구를 앞세울지 등)을
짜는 것도 유효한 전략입니다.

### `matchups: pandas.DataFrame` — 투수-타자 통산 맞대결 기록

컬럼: `pitcherPCode, hitterPCode, AVG, PA, AB, H, 2B, 3B, HR, RBI, BB, HBP, SO, SLG, OBP, OPS`

이번 호출 상황에 관련된 조합만 담겨 있습니다:
- 공격 턴(`is_offense=True`)이면 "우리 타자 × 상대 투수" 조합만.
- 수비 턴(`is_offense=False`)이면 "우리 투수 × 상대 타자(직전 라인업 기준)" 조합만.

**기록이 없는 조합은 이 표에 아예 나타나지 않습니다.** 없다고 걱정할 필요는 없습니다 — 시뮬레이션
엔진이 그 경우 개인 스탯 기반으로 알아서 처리하므로, 여러분은 이 표에 실제로 있는 것만 참고하면
됩니다.

### `context: dict`

| 키 | 타입 | 설명 |
|---|---|---|
| `inning` | int | 현재 이닝 (1~9. 연장은 없으므로 9를 넘지 않습니다) |
| `half` | `"top"` \| `"bottom"` | 이 명단이 실제로 쓰일 하프이닝 |
| `my_score`, `opponent_score` | int | 이닝 시작 시점 스코어 |
| `outs` | int | 항상 0 (이닝 시작 시점이므로) |
| `batting_order_start_index` | int (0~8) | 이번에 반환할 9명 리스트 중 몇 번 인덱스부터 타순이 시작되는지 (공격/수비 모두 제공; 수비팀은 "상대의 이번 타순 시작 번호" 참고용) |
| `my_prev_lineup` | `[pCode,...]` \| `None` | 우리 팀이 직전에 제출했던 라인업 (없으면 `None`) |
| `opponent_prev_lineup` | `[pCode,...]` \| `None` | 상대가 직전 이닝에 제출했던 라인업 |
| `opp_pitcher_pcode` | int \| `None` | **공격 턴에만 제공.** 이번 하프이닝 상대 투수 |
| `opp_catcher_pcode` | int \| `None` | **공격 턴에만 제공.** 이번 하프이닝 상대 포수 |
| `time_budget_sec` | float | 이 함수에 주어진 제한시간(초). 기본 10.0 |

### `rng: random.Random`
이 호출 전용 난수 생성기입니다. **난수가 필요하면 반드시 이 `rng`만 쓰세요** (`rng.random()`,
`rng.shuffle(...)`, `rng.choice(...)` 등). 전역 `random` 모듈이나 `random.seed()`를 써도 시뮬레이션
결과(안타/삼진 등)에는 아무 영향을 주지 못합니다(엔진 RNG와 완전히 분리) — 다만 여러분 알고리즘
자체의 동작을 재현 가능하게 하려면 이 `rng`를 쓰는 것이 유일한 방법입니다.

## 3. 반환값(출력) 스펙

| | 공격 (`is_offense=True`) | 수비 (`is_offense=False`) |
|---|---|---|
| 반환 타입 | pCode 정수 리스트 | pCode 정수 리스트 |
| 길이 | **9** | **10** |
| 순서 | 타순 1번 → 9번 | `[내야수, 내야수, 내야수, 내야수, 외야수, 외야수, 외야수, 포수, DH, 투수]` |
| 투수 포함 | 포함 안 함 (DH가 대신 타석에 섬) | **마지막(10번째) 자리에 반드시 포함** |

**검증 규칙** (하나라도 어기면 그 명단은 무효 처리됩니다 — 5절 참고):
1. 길이가 정확히 9(공격) / 10(수비)여야 합니다.
2. 같은 pCode를 중복해서 넣을 수 없습니다.
3. 모든 pCode는 `my_team`에 있는 우리 팀 선수여야 합니다(상대 팀 선수 불가).
4. 공격 라인업에는 투수(실제 `position == '투수'`)가 포함될 수 없습니다.
5. 수비 라인업의 마지막(10번째) 자리는 반드시 실제 투수여야 하고, 나머지 9자리에는 투수가
   들어갈 수 없습니다.
6. (실격은 아니지만 불이익) 내야수/외야수/포수/DH 자리에 실제 포지션이 다른 선수를 넣으면
   그 선수가 관여하는 수비 플레이의 실책 확률이 50% 증가합니다.

## 4. 샘플 코드

`examples/student_algorithm_template.py`를 그대로 복사해서 시작하면 됩니다 (아래는 그 파일의
전체 내용입니다):

```python
import random

import pandas as pd


def decide_lineup(is_offense: bool, my_team: pd.DataFrame, opponent_team: pd.DataFrame,
                   matchups: pd.DataFrame, context: dict, rng: random.Random):
    # ------------------------------------------------------------------
    # 0) 자주 쓰는 형태로 미리 캐싱 (매 적합도 평가마다 DataFrame 필터링 금지!)
    # ------------------------------------------------------------------
    batters = my_team[my_team["role"] == "타자"]
    pitchers = my_team[my_team["role"] == "투수"]
    batter_stat = {row["pCode"]: row for _, row in batters.iterrows()}       # pCode -> Series
    pitcher_stat = {row["pCode"]: row for _, row in pitchers.iterrows()}
    matchup_lookup = {(row["pitcherPCode"], row["hitterPCode"]): row for _, row in matchups.iterrows()}

    ifs = batters[batters["position"] == "내야수"]["pCode"].tolist()
    ofs = batters[batters["position"] == "외야수"]["pCode"].tolist()
    cs = batters[batters["position"] == "포수"]["pCode"].tolist()
    all_batter_codes = batters["pCode"].tolist()
    all_pitcher_codes = pitchers["pCode"].tolist()

    # ------------------------------------------------------------------
    # 1) 간단한 적합도(fitness) 함수 예시 - OPS와 체력을 이용한 아주 단순한 점수.
    #    실제 과제에서는 이 부분을 여러분의 메타휴리스틱 탐색으로 대체하세요.
    # ------------------------------------------------------------------
    def batter_score(pcode):
        row = batter_stat[pcode]
        ops = row.get("OPS", 0.6) or 0.6
        health = (row.get("health_pct", 100) or 100) / 100.0
        return ops * (0.5 + 0.5 * health)  # 체력이 떨어지면 점수 하락

    def pitcher_score(pcode):
        row = pitcher_stat[pcode]
        era = row.get("ERA", 5.0) or 5.0
        health = (row.get("health_pct", 100) or 100) / 100.0
        return (1.0 / (era + 1.0)) * (0.5 + 0.5 * health)

    # ------------------------------------------------------------------
    # 2) TODO: 여기를 Tabu Search / PSO / GA로 교체하세요.
    #    예: 공격 - 타순(순열) 최적화 / 수비 - 포지션 배정 최적화
    #    아래는 "점수 높은 순으로 그리디하게 채우는" 매우 단순한 자리표시자(placeholder)입니다.
    # ------------------------------------------------------------------
    if is_offense:
        ordered = sorted(all_batter_codes, key=batter_score, reverse=True)
        lineup = ordered[:9]
        rng.shuffle(lineup)  # (예시일 뿐 - 실제로는 타순 최적화 로직으로 대체)
        return lineup

    # 수비: 포지션별 상위 점수 선수 + 나머지 중 1명 DH + 최고점 투수
    chosen_if = sorted(ifs, key=batter_score, reverse=True)[:4]
    chosen_of = sorted(ofs, key=batter_score, reverse=True)[:3]
    chosen_c = sorted(cs, key=batter_score, reverse=True)[:1]
    used = set(chosen_if) | set(chosen_of) | set(chosen_c)
    remaining = [p for p in all_batter_codes if p not in used]
    dh = sorted(remaining, key=batter_score, reverse=True)[0] if remaining else all_batter_codes[0]
    pitcher = sorted(all_pitcher_codes, key=pitcher_score, reverse=True)[0]

    return chosen_if + chosen_of + chosen_c + [dh, pitcher]
```

이 템플릿 자체는 탐색을 전혀 하지 않는 단순 그리디입니다(참고용 출발점). `examples/` 폴더에는
실제로 동작하는 메타휴리스틱 구현 세 가지가 더 있으니, 베끼기보다 **각각이 이 문제의 어느 부분을
어떻게 인코딩했는지** 비교해 보는 걸 권장합니다.

| 파일 | 알고리즘 | 무엇을 탐색하는가 |
|---|---|---|
| `example_ga_lineup.py` | GA | 타순 **순열** (순서 교차 OX + 교환 돌연변이 + 엘리트 보존) |
| `example_tabu_lineup.py` | Tabu Search | 수비 10칸 **배정** (교환/교체 이웃, 타부 리스트, 열망 기준) |
| `example_pso_lineup.py` | PSO | 선수 평가 **가중치 벡터**(연속값) → 라인업으로 디코딩 |
| `strategy_fatigue_rotation.py` | (탐색 없음) | 체력 관리 규칙만 지키는 대조군 — 이걸 못 이기면 적합도 함수를 의심하세요 |
| `strategy_naive_best.py` | (탐색 없음) | ⚠️ 잘못된 예시: 에이스 혹사·체력 무시 |

- 난수는 반드시 인자로 받은 `rng`만 사용하세요.
- 반환값은 항상 **`my_team`에 있는 pCode 정수**로만 채우세요.
- 공격은 길이 9(투수 제외), 수비는 길이 10(마지막이 반드시 실제 투수)를 지키세요.
- `my_team`/`opponent_team`의 `role` 컬럼으로 타자/투수를 먼저 나눠서 쓰세요(2절 컬럼명 겹침 주의 참고).
- 함수 시작 시 자주 쓰는 값을 dict/array로 한 번만 캐싱해서 쓰세요(적합도 평가마다 DataFrame을
  반복 필터링하지 마세요 — 6절 참고).
- 체력(`health_pct`, `pitch_count`/`pitch_target`, `swing_count`/`swing_target`)을 적합도 함수에
  반영하세요 — 이 게임에서 가장 큰 승부처는 타순보다 **투수/체력 자원 관리**입니다.
- 제출 전에 로컬에서 직접 실행해 제한시간 안에 끝나는지, 반환값이 규칙에 맞는지 확인하세요(7절).
- 제출 파일이 서버에 업로드되면 뜨는 자동 검사 결과를 반드시 확인하세요(8절) — 오류가 있으면
  경기 자체가 시작되지 않습니다.

## 6. 하면 안 되는 것 (DON'T)

- 인자 이름을 바꿔 쓰지 마세요(예: `def decide_lineup(off, team, opp, ...)`) — 엔진이 키워드
  인자로 호출하므로 이름이 다르면 **오류**로 실격됩니다.
- 전역 `random` 모듈이나 `random.seed()`를 쓰지 마세요 — 규칙 위반(경고)이며, 애초에 경기 결과에
  영향도 주지 못합니다.
- `input()`, `sys.exit()`/`exit()`/`quit()`, `os._exit()`를 호출하지 마세요 — 프로세스가 멈추거나
  종료되어 반드시 실격(타임아웃/크래시) 처리됩니다.
- `os.system()`, `subprocess.*` 등 외부 명령 실행은 금지입니다.
- 파일을 직접 열지(`open()`) 마세요 — 필요한 데이터는 전부 인자로 전달됩니다.
- `time.sleep()`을 넣지 마세요 — 제한시간만 소모해 타임아웃 실격으로 이어집니다.
- 탈출 조건이 불확실한 `while True` 등 무한루프 가능성이 있는 코드를 넣지 마세요 — 시간 초과 시
  엔진이 강제 종료합니다.
- `global` 변수로 이닝 간 캐시를 만들려 하지 마세요 — **매 호출마다 완전히 새 프로세스에서
  실행되므로 전역 변수에 저장한 값은 다음 호출로 이어지지 않습니다.** 캐싱이 필요하면 함수
  안에서 매번 새로 만드세요.
- `os`, `subprocess`, `socket`, `shutil`, `urllib`, `requests`, `pickle`, `multiprocessing`,
  `threading`, `ctypes`, `importlib` 등 라인업 결정과 무관한 모듈은 import하지 마세요(경고
  대상이며, 파일/네트워크/프로세스 조작은 채점 환경에서 차단되거나 실격 사유가 될 수 있습니다).
- 반환 리스트에 상대 팀 선수, 존재하지 않는 pCode, 중복 선수, 투수를 공격 라인업에 넣는 것,
  수비 라인업 마지막 자리 외에 투수를 넣는 것 — 전부 검증 실패(무효 라인업)로 처리됩니다.
- population/세대수/타부 반복 횟수를 과도하게 키우지 마세요(7절 권장치 참고) — 제한시간을
  넘기면 그 이닝은 실격 처리됩니다.

## 7. 제출하면 바로 자동 검사됩니다

파일을 서버(라이브 뷰어)에 올리는 순간 코드가 자동으로 검사되어 화면에 바로 뜹니다. **오류가
하나라도 있으면 경기를 시작할 수 없습니다.**

| 구분 | 걸리는 것 |
|---|---|
| 🚫 오류 (경기 불가) | 문법 오류 · `decide_lineup` 함수 없음 · 클래스/다른 함수 안에 정의함 · **인자 개수·이름이 다름** · `return` 문 없음 · `input()` · `sys.exit()`/`exit()`/`quit()`/`os._exit()` · `os.system()`/`subprocess.*` |
| ⚠ 경고 | 전역 `random` 사용(→ `rng`로 바꾸세요) · `random.seed()` · numpy 난수 · `time.sleep()` · `while True` · `os`/`requests` 등 불필요한 모듈 · 파일 열기(`open()`) |
| ℹ 참고 | `print()`(디버깅용이면 제출 전에 지우는 게 좋습니다) · `global`(이닝 간 값이 이어지지 않음) · 파일 최상위 실행문(매 호출마다 다시 실행되어 무거우면 시간 소모) |

여기에 더해 **실제로 공격/수비 한 번씩 함수를 호출**해서 ① 예외 없이 끝나는지 ② 제한시간
안에 들어오는지 ③ 반환한 명단이 위 3절 검증 규칙을 지키는지까지 확인하고, 걸린 시간과 실제로
뽑힌 선수 명단을 화면에 보여줍니다. 이 스모크 테스트를 통과해야 매치가 시작됩니다.

**실행 중 실격되면 어떻게 되는가**: 실제 경기 도중(스모크 테스트가 아니라) 타임아웃/예외/규칙
위반이 발생하면, 그 하프이닝은 **직전에 제출했던 유효한 라인업으로 자동 대체**됩니다(그마저
없으면, 예를 들어 1이닝 초처럼 이전 기록이 없으면 기본 출전 명단으로 대체). 경기 자체가 멈추지는
않지만, 매 이닝 여러분의 전략이 반영되지 못하므로 승부에는 확실히 불리합니다.

## 8. 실행시간 가이드 (사전 벤치마크 결과)

같은 반 학생들의 전형적인 구현을 벤치마크한 결과, 아래를 지키면 대부분 기본 제한시간(10초)에
여유 있게 들어옵니다.

- population ≤ 100, generation ≤ 200, tabu iteration ≤ 300 정도를 권장합니다.
- 적합도 함수 안에서 `my_team[my_team['team']==...]` 같은 DataFrame 필터링을 **매번** 하지
  마세요. 함수 시작할 때 한 번 dict로 캐싱해두고 쓰세요(4절 샘플 코드 참고). 이걸 안 하면
  몇 초가 그냥 날아갑니다.
- 적합도 평가 안에서 몬테카를로 반복(수십 회 이상 시뮬레이션 재실행 등)은 population/세대수와
  결합되면 아주 쉽게 10초를 넘깁니다. 분산을 줄이고 싶다면 반복 횟수를 최소화하거나, 근사식
  (예: OPS/ERA 기반 폐쇄형 점수)으로 대체하는 걸 권장합니다.

## 9. 로컬에서 테스트하기

제출 전에 미리 확인해 보세요. 두 가지 방법이 있습니다(자세한 사용법은 운영 매뉴얼 7절 참고).

**방법 A — 라이브로 눈으로 보면서 (추천)**

```bash
python -m kbo_sim.server
```

호출되며, 뽑힌 출전명단·이닝별 계산시간·실격(타임아웃/예외/규칙위반) 여부를 화면에서 바로

```bash
python -m kbo_sim.cli \
  --a-name 내이름 --a-team 삼성 --a-algo my_algo.py \
  --b-name 상대이름 --b-team KT --b-algo examples/baseline_random_algorithm.py \

```

## 10. 자주 하는 실수

1. **인자 이름을 바꿔 쓰기** (`def decide_lineup(off, team, opp, ...)`) → 엔진이 키워드로
   호출하므로 **오류**입니다. 이름과 순서를 원본 그대로 두세요.
2. **`global`로 캐시를 만들어 다음 이닝에 재사용하려는 시도** → 매 호출마다 완전히 새 프로세스에서
   실행되므로 값이 남지 않습니다. 캐싱은 함수 안에서 매번 새로 만드세요.
3. **컬럼명 겹침을 무시하고 `my_team["ERA"]`처럼 role 구분 없이 접근** → 타자 행에서는 `NaN`이
   나옵니다. 반드시 `role`(또는 `position`)로 먼저 나눠서 접근하세요.
4. **방어율/타율만 보고 선수를 고르는 것** → 표본이 아주 적은 선수(예: 2이닝만 던진 불펜)는
   극단적인 수치가 나올 수 있고, 무엇보다 `health_pct`/`pitch_target`을 무시하면 체력 관리
   실패로 후반에 급격히 무너집니다.
5. **적합도 평가 안에서 매번 DataFrame을 필터링** → population/세대수와 곱해지며 실행시간이
   기하급수적으로 늘어 타임아웃 실격으로 이어집니다.

## 11. 기타 참고 사항

- 여러분의 함수는 이닝마다 **매번 새 프로세스에서 새로 임포트되어 실행**됩니다(격리 실행). 즉
  모듈 최상위에 있는 무거운 초기화 코드도 매 호출마다 다시 실행되니 주의하세요.
- `my_team`/`opponent_team`은 매 호출 시점의 **스냅샷**입니다. 여러분이 DataFrame 자체를 수정해도
  다음 호출에는 영향을 주지 않습니다(엔진이 매번 새로 만들어 전달합니다).
- 상대 팀 선수들의 체력·기록도 전부 보인다는 점(`opponent_team`)을 전략에 적극 활용하세요 —
  상대 투수가 이미 지쳤다면 그 이닝에 강한 타자를 앞세우는 식의 상황 인지형 전략이 가능합니다.
- 표준 라이브러리, `pandas`, `numpy`는 자유롭게 사용 가능합니다. 그 외 외부 패키지는 채점
  환경에 없을 수 있으므로 사용하지 마세요.
- 궁금한 점이 있으면 원본 스펙(`kbo_sim/student_api.py` 파일 상단 docstring)을 직접 확인하거나
  강사에게 문의하세요.
