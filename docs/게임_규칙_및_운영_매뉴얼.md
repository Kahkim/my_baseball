# 나의 구단주가 되어라 — 게임 규칙 및 운영 매뉴얼

이 문서는 **게임 자체가 어떻게 굴러가는지(규칙)**와 **프로그램을 어떻게 실행/운영하는지**를 다룹니다.
"내가 구현해야 하는 함수 자체"의 상세 스펙(인자/반환값/샘플코드/금지사항)은 별도 문서
[`프로그램_매뉴얼.md`](./프로그램_매뉴얼.md)에 있습니다 — 코드를 짜기 전 그 문서를 먼저 읽으세요.

---

## 1. 이 과제가 무엇인가

메타휴리스틱(Tabu Search / GA / PSO 등) 수업 프로젝트입니다. 여러분이 실제로 짜는 것은 **함수
하나**입니다: 경기 중 매 이닝 시작마다 호출되어 "이번 이닝에 누구를 내보낼지"를 결정하는
`decide_lineup()`. 이 함수가 여러분의 구단주 역할을 대신합니다.

여러분의 알고리즘은 실제 KBO 시즌 기록을 바탕으로 한 가상의 경기 시뮬레이션 위에서, 다른 학생이
제출한 알고리즘과 **3연전**을 치릅니다. 같은 데이터를 갖고도 어떤 전략(누구를 언제 얼마나 쓰는가)을
쓰느냐에 따라 승률이 크게 갈리도록 설계되어 있습니다.

## 2. 데이터에 대한 투명성 고지

- 선수 개인 성적(타율·출루율·장타율·방어율·투구수 등)과 안타/홈런/삼진 등 경기 결과 확률은
  **실제 KBO 정규시즌 공식 최종 기록**에 기반합니다.
- 다만 도루 적극성, 수비 실책 기초율처럼 **공식 기록에 아예 존재하지 않는 항목**은 시뮬레이션
  엔진이 선수 고유번호와 경기 시드로부터 결정론적으로 만들어낸 **합성값**입니다. 같은 시드로는
  항상 같은 값이 나오지만(재현 가능), "이 선수가 실제로 이런 성향이었다"는 사실 주장이 아닙니다.
  화면에도 이런 값은 "엔진 성향치"로만 표시됩니다.
- 투수-타자 맞대결(상성) 기록은 실제 맞대결 데이터가 있으면 그 표본 크기에 비례해 신뢰하고,
  없으면 개인 스탯 기반 추정으로 자연스럽게 대체됩니다 (아래 5절 참고).

## 3. 경기 진행 규칙

- **9이닝 정규경기**, 연장전은 없습니다. 9회까지 마쳤는데 동점이면 그대로 **무승부**로 종료됩니다.
- **콜드게임(머시룰)**: 5회 이후 한쪽이 10점 이상 앞서 있으면, **그 하프이닝이 끝나는 시점에**
  경기가 조기 종료됩니다(이닝 도중에 끊지 않습니다). 단, 정규 마지막 이닝(9회)만은 예외입니다 —
  점수 차가 아무리 커도 홈팀의 마지막 공격 기회는 반드시 보장되며, 9이닝을 끝까지 다 치른 경기는
  점수 차가 크더라도 "콜드게임"으로 표시되지 않습니다(정규 종료).
- **끝내기**: 9회말(또는 그 경기의 마지막 정규이닝 말)에 홈팀이 역전하는 순간, 그 타석에서 즉시
  경기가 종료됩니다.
- **라인업 구성**
  - 공격: 9명 (타순 순서대로, **투수는 제외**하고 대신 DH가 타석에 섭니다)
  - 수비: 10명, 순서 고정 — `[내야수, 내야수, 내야수, 내야수, 외야수, 외야수, 외야수, 포수, DH, 투수]`
- **포지션 고정 규칙**
  - 투수 자리에는 반드시 실제 포지션이 "투수"인 선수만 들어갈 수 있습니다(외야수를 투수로 올리는
    것 등은 불가능).
  - 그 외 자리(내야수/외야수/포수/DH)는 투수가 아닌 어떤 타자든 배치할 수 있지만, **슬롯이 요구하는
    포지션과 그 선수의 실제 고정 포지션이 다르면 그 선수가 관여하는 수비 플레이의 실책 확률이
    50% 증가**합니다. DH는 수비를 보지 않으므로 이 페널티가 없습니다.
- **이닝 도중 교체/작전 없음**: 이닝이 시작될 때 그 이닝 내내 쓸 전체 명단(공격/수비)을 한 번에
  확정합니다. 이닝 중간 선수 교체, 대타/대주자, 번트·도루 지시 같은 개별 작전은 없습니다 —
  번트와 도루는 각 선수 고유의 성향(번트 적극성/도루 적극성)에 따라 **엔진이 자동으로 판단**합니다.
- **체력은 회복되지 않습니다.** 경기 내내 누적됩니다.
  - 타자/야수는 스윙 20회 안팎(선수마다 목표치가 ±20% 무작위로 다름)을 기준으로 능력치가
    급격히 떨어지기 시작합니다. 타격 스윙과 수비 이닝(1이닝당 스윙 환산 3~5회 소모)이 같은
    체력 풀을 공유합니다.
  - 투수는 그 선수의 **실제 KBO 등판당 평균 투구수** 근처(역시 ±20% 개인차)에서 급락합니다.
    방어율이 아무리 좋아도 원래 짧게 던지던 불펜 투수를 선발처럼 오래 쓰면 급격히 무너집니다.
  - "잘하는 선수가 항상 잘하지는 않도록" 목표치 자체에 개인차를 랜덤으로 부여해 두었습니다 —
    즉 같은 선수라도 경기마다 실제로 버티는 체력이 조금씩 다릅니다.
- **타석 처리 순서**: 엔진은 그 타석의 **결과(안타/홈런/삼진/사사구 등)를 먼저 확률적으로 결정**한
  뒤, 그 결과에 맞는 그럴듯한 투구 시퀀스(볼카운트 진행)를 **역으로 만들어** 중계합니다.
- 자세한 라인업 함수 호출 시점(이닝당 몇 번, 어떤 순서로 호출되는지)은 4절, 함수 자체의 완전한
  스펙은 [`프로그램_매뉴얼.md`](./프로그램_매뉴얼.md)를 참고하세요.

## 4. 알고리즘 호출 시점 (요약)

`decide_lineup()`은 **이닝이 시작될 때 한 번에 4번** 호출됩니다 (두 팀 × 공격/수비):

```
N회 시작
 ① 홈팀 수비 결정  (초 수비에 쓰임)
 ② 원정팀 수비 결정 (말 수비에 쓰임)
 ③ 원정팀 공격 결정 (초 공격에 쓰임)
 ④ 홈팀 공격 결정  (말 공격에 쓰임)
 → N회초 진행 → N회말 진행 → (N+1)회 시작 → ...
```

수비를 먼저 정하기 때문에 공격 명단을 정할 때는 그 이닝에 상대할 투수/포수를 이미 알 수 있습니다.
다만 **말 공격 명단도 초가 진행되기 전에(=이닝 시작 시점에) 확정**되므로, 홈팀이라면 초 공격에서
벌어진 일(점수 변화, 초에서 소모된 상대 체력 등)이 아직 반영되지 않은 상태에서 말 공격 라인업을
결정하게 됩니다. 공수교대 때는 다시 호출되지 않습니다.

## 5. 여러분의 알고리즘은 시뮬레이션 결과를 조작할 수 없습니다

시뮬레이션 엔진은 두 개의 완전히 분리된 난수 발생기를 씁니다 — 하나는 안타/삼진 등 **경기
결과**를 굴리는 엔진 전용 RNG, 다른 하나는 여러분의 `decide_lineup()`에 인자로 전달되는 `rng`
입니다. 여러분 코드가 전역 `random` 모듈을 쓰거나 `random.seed()`를 호출해도 경기 결과(안타가
나올지 등)에는 **전혀 영향을 주지 못합니다.** 대신 `rng`는 여러분 알고리즘 자체(탐색 과정 등)를
재현 가능하게 만들기 위해서만 존재합니다.

## 6. 3연전 시리즈 규칙

두 학생이 맞붙으면 팀·홈원정 편향을 상쇄하기 위해 자동으로 3경기를 치릅니다:

| 경기 | 구성 |
|---|---|
| 1차전 | 각자 처음 선택한 팀 그대로 |
| 2차전 | 두 학생이 팀을 **서로 바꿔서** |
| 3차전 | 어느 학생이 어느 팀을 맡을지, 홈/원정까지 **완전 무작위 재배정** |

각 경기 결과는 승 1점 / 무 0.5점씩 / 패 0점으로 집계되고, 3경기 합산 점수가 높은 쪽이 매치
승자입니다(합산 점수가 같으면 무승부). 같은 시드를 쓰면 대진표(누가 어떤 팀으로 몇 차전에
붙는지)도 항상 똑같이 재현됩니다.

## 7. 프로그램 실행 방법

설치는 이것뿐입니다: `pip install pandas numpy` (파이썬 표준 라이브러리 외에 이 두 개만 있으면
됩니다).

### 방법 A — 라이브 중계 (수업 시연·눈으로 보면서 테스트할 때 권장)

```bash
python -m kbo_sim.server
```

브라우저가 자동으로 열립니다(`http://127.0.0.1:8000`). 화면에서:

1. **이름 / 구단 선택 / 알고리즘 .py 파일 드래그&드롭**을 두 학생 모두 진행합니다. 파일을
   올리는 즉시 서버가 코드를 자동 검사하고 결과를 화면에 띄웁니다 (문법·시그니처 오류, 위험한
   호출, 실제 1회 실행 테스트까지 — 자세한 검사 항목은 프로그램 매뉴얼 8절 참고). **오류가
   하나라도 있으면 경기 시작 버튼이 잠깁니다.**
2. **[3연전 시작]**을 누르면 1차전부터 순서대로 진행됩니다.
3. 진행 버튼은 이닝마다 역할이 바뀌며 클릭합니다:
   - **[다음 라인업 선발 (N회)]** — 이닝 시작에 딱 한 번, 두 학생의 알고리즘이 4번 호출되어
     그 이닝에 쓸 명단이 전부 확정됩니다.
   - **[다음 공격 진행 (N회초 / N회말)]** — 확정된 명단으로 그 하프이닝을 실제로 진행합니다.
   (미리 다 계산해 둔 로그를 재생하는 게 아니라, 버튼을 누르는 시점에 실제로 알고리즘이 호출됩니다.)
4. **[자동진행]**은 버튼을 자동으로 눌러 이닝을 이어가되, **한 경기(예: 1차전)가 끝나면
   자동으로 멈춥니다.** 3연전 전체를 자동으로 넘기지 않으므로, 매 경기 최종 스코어를 확인한
   뒤 직접 [다음 경기 시작]을 눌러야 합니다.
5. 화면에서 실시간으로 볼 수 있는 것: 야구장 그라운드 시각화(수비 배치·타구 궤적·주자·아웃카운트),
   이닝별 스코어보드, 양 팀 출전명단(타순/포지션/체력/포지션 불일치 표시), **이닝별·팀별 알고리즘
   계산시간 표**, 투구 단위 문자중계(아웃은 빨간색으로 표시됩니다).

미리 팀/파일을 지정해서 띄우려면:
```bash
python -m kbo_sim.server --a-name 김학생 --a-team 삼성 --a-algo submissions/kim.py \
                          --b-name 이학생 --b-team KT   --b-algo submissions/lee.py --seed 42
```

### 방법 B — 일괄 채점 (여러 조를 한 번에 돌릴 때, 결과만 빠르게 볼 때)

```bash
python -m kbo_sim.cli --a-name 김학생 --a-team 삼성 --a-algo submissions/kim.py \
                       --b-name 이학생 --b-team KT   --b-algo submissions/lee.py \
                       --seed 42 --timeout 10 --out output
```

3연전이 화면 진행 없이 끝까지 자동으로 진행되고 `output/game1.json`, `game2.json`, `game3.json`,
`match_summary.json`이 생성됩니다. 생성된 JSON은 `viewer/broadcast_viewer.html`을 브라우저로 열어
파일을 선택하면 처음부터 되돌려볼 수 있습니다.

> 같은 시드를 쓰면 방법 A(라이브)와 방법 B(일괄)의 결과는 **완전히 동일**합니다 — 내부적으로
> 같은 상태머신과 같은 대진표 생성 로직을 공유하기 때문입니다.

**주요 인자**

| 인자 | 의미 | 기본값 |
|---|---|---|
| `--a-name`, `--b-name` | 학생 이름 | (필수) |
| `--a-team`, `--b-team` | 소속 구단 (삼성/KT/LG/KIA/두산/NC/롯데/SSG/한화/키움) | (필수) |
| `--a-algo`, `--b-algo` | 제출 파일 경로 | (필수) |
| `--seed` | 대진표·경기 결과 재현용 시드 | 무작위 |
| `--timeout` | `decide_lineup()` 1회 호출 제한시간(초) | 10.0 |
| `--out` | 결과 JSON 저장 폴더 (cli만 해당) | `output` |
| `--data-dir` | 데이터 폴더 직접 지정(보통 필요 없음) | `kbo_sim/data_snapshot/` |

### 성능 감 잡기

```bash
python tools/calibrate.py
```
이 게임의 득점 환경을 볼 수 있습니다. 투수를 매 이닝 적절히 교체하면 9이닝 4~5점대(KBO 현실과
비슷한 수준)이지만, 한 투수를 끝까지 혹사시키면 9이닝 10점 안팎까지 무너집니다. **투수 체력
관리가 이 게임에서 가장 크게 승부를 가르는 요인**입니다.
