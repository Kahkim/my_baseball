# 게임 규칙 및 운영 매뉴얼

이 문서는 경기 규칙과 실행·제출·결과 확인 방법을 설명합니다.
함수의 인자와 반환값은 [프로그램 매뉴얼](프로그램_매뉴얼.md), 설치부터 시작하려면 [README](../README.md)를 보세요.
아래 규칙은 현재 배포 코드의 기본 설정을 기준으로 합니다.

## 1. 학생이 하는 일

여러분은 `decide_lineup()` 함수를 작성해 **이닝마다 출전선수와 타순을 결정**합니다.
한 타석의 스윙이나 투구를 조작하는 게임은 아닙니다. Tabu Search·GA·PSO 등으로 명단을 탐색하고,
체력·기록·상대 투수 등을 고려한 전략을 다른 알고리즘과 비교합니다.

| 용어 | 이 게임에서의 뜻 |
|---|---|
| 이닝 | 1회, 2회처럼 경기를 나누는 단위. 보통 초와 말로 구성 |
| 하프이닝 | 초 또는 말. 원정팀은 초에, 홈팀은 말에 공격 |
| 타석 | 한 타자의 공격 기회 |
| 라인업 | 반환한 선수 명단. 공격은 타순, 수비는 자리 배정 순서 |
| DH(지명타자) | 수비 명단에 포함되지만 실제 수비에는 나가지 않는 자리 |
| 폴백 | 알고리즘 호출이 실패했을 때 엔진이 대신 사용하는 명단 |

## 2. 한 이닝의 진행

이닝 시작에 각 팀의 `decide_lineup`을 한 번씩, **총 2회** 호출합니다. 학생 한 명당 한 번
호출되어 그 이닝의 수비 10명과 공격 타순 9명을 한꺼번에 반환합니다.

```text
N회 시작
  ① 홈팀 decide_lineup 1회 → 수비 10명 + 타순 9명 확정 (이 이닝 내내 고정)
  ② 원정팀 decide_lineup 1회 → 수비 10명 + 타순 9명 확정 (이 이닝 내내 고정)
N회초 진행(원정 공격/홈 수비) → N회말 진행(홈 공격/원정 수비) → 다음 이닝
```

두 팀 명단을 이닝 시작에 동시에 정하므로 **이번 이닝에 상대할 투수·포수는 아직 알 수 없습니다**
(`context`의 `opp_pitcher_pcode` 등은 직전 이닝 기준, 1회엔 없음).
두 팀 모두 이닝 시작 시점의 점수와 체력을 보고 결정하므로, **홈팀의 말 공격 명단에도 아직 초 공격 결과는 반영되지 않습니다.**

공수교대 때 다시 호출하지 않습니다. 이닝 중 대타·대주자·투수 교체나 번트·도루 지시는 없고,
번트와 도루는 엔진이 상황과 성향에 따라 결정합니다. 경기가 조기 종료되면 미리 정한 명단 일부를 사용하지 않을 수 있습니다.

## 3. 출전 명단과 타순

`decide_lineup`은 `{"defense": [10명], "offense": [9명]}` dict를 반환합니다.

| 키 | 반환 명단 | 반드시 지킬 조건 |
|---|---|---|
| `offense` | 타자 9명, 1번부터 9번 순서 | `defense` 앞 9명(투수 제외)과 같은 9명, 중복 없음 |
| `defense` | 내야 4명 → 외야 3명 → 포수 → DH → 투수 | 총 10명, 중복 없음, 마지막 자리만 실제 투수 |

수비의 앞 9자리에는 우리 팀의 타자를 넣습니다. 내야수·외야수·포수는 서로 다른 포지션의 타자를 배치해도
명단 자체가 무효가 되지는 않습니다. 다만 해당 선수가 타구를 처리할 때, 포지션 불일치에 따른 실책 배수 **1.5배**가 적용됩니다.
이는 50%포인트를 더한다는 뜻이 아닙니다. **DH에는 이 수비 페널티가 없습니다.**
현재 일반 타구 처리 로직이 고르는 수비수는 내야수·외야수·투수이며, 포수의 도루 저지 능력은 별도로 모델링하지 않습니다.

**공격 9명은 수비 명단의 앞 9명과 반드시 같아야 합니다(DH 포함).** 타순과 수비 자리의 표시 순서는 달라도 선수는 같습니다. 투수는 타격하지 않으며, 공수교대 때도 같은 투수를 유지합니다.
선수·투수 교체는 다음 이닝 시작에만 가능합니다. 이전 이닝에 빠졌던 선수를 다시 골라도 됩니다. 같은 선수의 체력은 이어집니다.

### 타순은 다음 이닝으로 이어집니다

매 이닝 새 타순을 반환할 수 있지만, 항상 리스트의 첫 선수부터 치지는 않습니다.
`context["batting_order_start_index"]`가 이번 공격을 시작할 인덱스입니다.

예를 들어 시작 인덱스가 `4`이고 반환값이 `[a, b, c, d, e, f, g, h, i]`라면
실제 공격 순서는 `e → f → g → h → i → a → …`입니다.
도루 실패로 3아웃이 되어 타석을 끝내지 못한 경우에는 타순을 넘기지 않습니다.

## 4. 체력 관리

체력은 **한 경기 안에서는 회복되지 않습니다.** 벤치에 쉬게 해도 이미 소모된 체력이 돌아오지는 않으며,
그 동안 추가 소모를 피할 수 있습니다. 다음 경기가 시작되면 누적 소모량을 초기화하고 새 경기 시드로 목표치를 정합니다.

| 선수 | 누적 소모 | 체력 저하 기준 |
|---|---|---|
| 타자·야수 | 타격 스윙 수 + 수비 소모 | `swing_target`: 16~24 범위에서 결정 |
| 투수 | 실제로 생성된 투구 수 | `pitch_target`: 등판당 평균 투구수를 바탕으로 결정 |

야수는 수비 하프이닝 시작에 1인당 스윙 환산 **3~5회**를 소모합니다.
수비 명단의 내야 4명·외야 3명·포수 1명에게 적용되고 DH와 투수는 이 소모에서 제외됩니다.

투수는 `NP_per_G = NP / G`를 바탕으로 기본 목표치를 15~140 사이로 보정한 뒤 ±20% 변동을 적용합니다.
실제 비교에는 이번 경기 값인 `pitch_target`과 누적값인 `pitch_count`를 사용하세요.
목표치는 등판 금지선이 아니라 능력이 빠르게 떨어지는 부근의 기준입니다.

화면의 `health_pct`는 소모량을 변환한 0~100 지표입니다. **50% 체력이 안타 확률 50%를 뜻하지는 않습니다.**
체력이 낮아져도 출전은 가능하며, 능력 저하가 확률과 수비에 반영됩니다.

## 5. 경기 종료 규칙

### 기본 종료와 끝내기

- 기본은 **9이닝**, 연장전은 없습니다. 9회 종료 시 동점이면 무승부입니다.
- 9회초가 끝났을 때 홈팀이 앞서 있으면 9회말을 하지 않고 종료합니다.
- 홈팀이 동점이거나 지고 있으면 9회말을 진행합니다.
- 9회말 홈팀이 앞서는 결승점을 내면 즉시 끝납니다. 홈런 외의 안타는 결승점까지 득점·타점을 인정하고 진루도 그 시점에 맞춥니다. 홈런은 타자와 주자 모두의 득점을 인정합니다.

예: 9회말 0:0, 만루에서 끝내기 안타가 나오면 **1:0**입니다. 같은 상황의 끝내기 홈런이면 **4:0**입니다.

### 콜드게임: 이 과제에서 정한 규칙

**5~8회에는 초 또는 말이 끝날 때 10점 이상 차이가 나면 콜드게임으로 종료**합니다.
하프이닝 도중에는 종료하지 않습니다. 현재 구현은 초 종료 직후에도 판정하므로,
원정팀이 5회초에 10점 앞서면 홈팀의 5회말 공격 없이 끝날 수 있습니다.

9회에는 콜드게임보다 위의 정규 종료 규칙을 적용합니다. 홈팀이 지고 있다면 점수 차와 관계없이 말 공격을 진행하며,
큰 점수 차로 정규 종료한 경기를 콜드게임으로 표시하지 않습니다.
이 규칙은 교육용 엔진의 운영 규칙이며 실제 KBO 규정 전체를 재현한 것은 아닙니다.

## 6. 3연전과 승점

두 학생은 **서로 다른 구단**을 고릅니다. 이름이 같아도 참가자 A/B로 따로 집계됩니다.

| 경기 | 학생 A | 학생 B |
|---|---|---|
| 1차전 | 처음 고른 구단, 원정 | 처음 고른 구단, 홈 |
| 2차전 | B가 고른 구단, 홈 | A가 고른 구단, 원정 |
| 3차전 | 두 구단 중 하나와 홈/원정을 무작위 배정 | 남은 구단과 반대 홈/원정 |

알고리즘 파일은 학생에게 붙어 있고, 맡는 구단만 바뀝니다. 특정 구단의 선수 번호를 코드에 고정하면
2차전 이후 유효한 명단을 만들지 못할 수 있으므로 반드시 `my_team`에서 선수를 고르세요.

각 경기 승리 1점, 무승부 0.5점, 패배 0점입니다. 합산 점수가 높은 학생이 3연전 승자이며 같으면 무승부입니다.

## 7. 실행하고 결과 확인하기

환경 준비는 [README의 빠른 시작](../README.md#빠른-시작)을 따릅니다. 모든 명령은 프로젝트 최상위 폴더에서 실행하세요.

### 라이브 화면으로 진행

```shell
python -m kbo_sim.server
```

1. 학생 A/B의 이름과 서로 다른 구단을 입력하고 `.py` 파일을 올립니다.
2. 검사에서 공격·수비 각각 한 번의 실행 결과를 확인합니다. 오류가 있으면 시작할 수 없고, 경고는 내용을 확인해 수정합니다.
3. **[경기 준비 완료 → 3연전 시작]**을 누릅니다.
4. **[다음 라인업 선발] → [다음 공격 진행(초)] → [다음 공격 진행(말)]**을 반복합니다. 조기 종료하면 남은 단계는 생략됩니다.
5. 자동진행도 경기마다 멈춥니다. 결과를 확인한 뒤 **[다음 경기 시작]**을 누릅니다.

라인업 버튼은 학생 알고리즘을 실행하고, 공격 진행 버튼은 확정된 명단으로 경기 엔진을 실행합니다.
화면에는 이닝별 점수(R), 안타(H), 실책(E), 명단·체력·계산시간·투구 중계가 표시됩니다.
새로고침하면 실행 중인 서버의 현재 경기 상태를 복구합니다. 서버를 종료하고 다시 켜면 진행 중 상태가 복구되지는 않습니다.

업로드는 매번 별도 폴더에 저장하므로 파일명이 같아도 덮어쓰지 않습니다.
한 번 올린 뒤 원본 파일을 수정했다면 화면에도 **다시 업로드**해야 변경 내용이 적용됩니다.

### 화면 없이 일괄 실행

아래는 저장소에 들어 있는 예제끼리 겨루는 명령입니다.

```shell
python -m kbo_sim.cli --a-name 학생A --a-team 삼성 --a-algo examples/student_algorithm_template.py --b-name 학생B --b-team KT --b-algo examples/baseline_random_algorithm.py --seed 42 --out output/example_match
```

| 옵션 | 서버 | CLI | 의미 |
|---|---|---|---|
| `--a-name`, `--b-name` | 선택 | 필수 | 학생 이름 |
| `--a-team`, `--b-team` | 선택 | 필수 | 구단 이름 |
| `--a-algo`, `--b-algo` | 선택 | 필수 | 제출 `.py` 경로 |
| `--seed` | 선택 | 선택 | 재현용 시드. 생략하면 무작위 |
| `--timeout` | 기본 10초 | 기본 10초 | 알고리즘 호출당 제한시간 |
| `--out` | 기본 `output` | 기본 `output` | 경기 결과 저장 폴더 |
| `--data-dir` | 선택 | 선택 | CSV 4개가 있는 데이터 폴더 |
| `--port` | 기본 8000 | 없음 | 서버 포트 |
| `--no-browser` | 선택 | 없음 | 브라우저 자동 열기 생략 |

사용할 수 있는 팀 이름은 `삼성`, `KT`, `LG`, `KIA`, `두산`, `NC`, `롯데`, `SSG`, `한화`, `키움`입니다.
서버는 기본적으로 `127.0.0.1`에 연결됩니다. 학생 Python 코드를 실행하므로 검토한 제출물을 사용하세요.
별도 프로세스 실행과 시간 제한이 파일·네트워크 접근 전체를 차단하는 보안 장치는 아닙니다.

### 저장 결과와 재현

라이브는 경기 종료마다 `game1.json`~`game3.json`을 저장합니다.
CLI는 이 파일들에 더해 `match_summary.json`을 저장합니다.
[리플레이 뷰어](../viewer/broadcast_viewer.html)를 브라우저로 열고 `gameN.json` 한 개를 선택하세요.
요약 JSON은 리플레이 입력이 아닙니다. 출력 폴더를 재사용하면 같은 파일을 덮어쓰므로 실험마다 폴더를 나누세요.

같은 데이터·엔진·제출 코드·시드·참가 구성을 유지하고, 전달된 `rng`만 사용하며 호출 성공/시간 초과 여부가 같다면
라이브와 CLI의 경기 결과를 재현할 수 있습니다. 다른 PC의 실행시간까지 같지는 않습니다.
여러 시드와 팀 배정으로 비교한 뒤 전략을 평가하세요. 한 번의 승패만으로 우열을 확정하기는 어렵습니다.

## 8. 데이터와 시뮬레이션의 범위

동봉된 `data_snapshot`의 시즌 기록을 읽습니다. 실행 시 최신 기록을 자동 수집하지 않습니다.
타석 확률은 개인 기록에 표본 크기 보정, 맞대결 기록, 체력과 무작위 변동을 반영해 계산합니다.

도루 성향·개인 실책 배수는 **동봉 CSV에 없는 항목**을 보완하는 합성값입니다.
번트 성향은 `SAC/PA` 기록에 합성 변동을 더합니다. 이는 실제 선수의 능력을 확정적으로 평가하는 수치가 아닙니다.

엔진은 도루·번트 여부를 처리한 뒤 타석 결과를 정하고, 결과에 맞는 투구 순서를 만들어 중계합니다.
화면의 투구와 타구 궤적은 실제 경기 기록을 재생하는 것이 아닙니다.
